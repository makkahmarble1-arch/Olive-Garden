# SEO Architecture

## 1. URL structure

All URLs are lowercase, hyphenated, without trailing slashes, and have one
clear search intent each.

```
/                                   Homepage: independent guide intro, featured categories, guides
/menu                               Main menu hub: all 17 categories (noindex until final content)
/[category]                         17 category pages at the root, e.g. /desserts, /lunch-menu
/blog                               Blog index
/blog/[slug]                        Blog articles (guides)
/about                              About + editorial/price-checking policy
/contact                            Contact / report a wrong price
/disclaimer                         Non-affiliation + price accuracy
/privacy-policy                     Privacy policy
/sitemap.xml                        Generated by app/sitemap.ts
/robots.txt                         Generated by app/robots.ts
```

### Approved category URLs (owner decision, 2026-11-11)

17 dedicated pages, root-level, exact slugs (full table:
`CONTENT_ARCHITECTURE.md` §2):

`/family-style-meals`, `/appetizers`, `/classic-entrees`, `/buy-one-take-one`,
`/amazing-alfredos`, `/soups-salad-and-breadsticks`, `/lighter-portions`,
`/create-your-own-pasta`, `/lunch-menu`, `/desserts`, `/drink-menu`,
`/sides-sauces-and-extras`, `/non-alcoholic-beverages`, `/wine-and-beer-to-go`,
`/gluten-sensitive`, `/kids-meal`, `/catering`.

- Category pages are **not** placed under `/menu/`.
- Built later as `app/[category]/page.tsx` with `generateStaticParams` and
  `dynamicParams = false` (unknown root paths return 404). Fixed routes
  (`/menu`, `/blog`, …) take priority; validation blocks reserved slugs.
- Not built until the owner approves each page's verified content.

### Rules to avoid duplicate intent

- **Homepage vs. `/menu` (owner decision: Option B).**
  - Homepage = independent website introduction, featured categories,
    important resources and guides, clear link to the full menu.
    It does **not** list all categories or repeat the hub content.
  - `/menu` = comprehensive menu overview: all 17 categories, grouped, with
    short category descriptions and (later) a verified price summary.
  - Different titles, H1s, and descriptions. Only `/menu` targets the general
    "Olive Garden menu" topic.
  - `/menu` is **noindex, follow** until its final verified content is ready
    and approved; then it becomes indexable.
- **Overlapping categories** (Amazing Alfredos ⊂ Classic Entrees, Lighter
  Portions ⊂ Lunch Menu, Drink Menu ⊂ Non-Alcoholic Beverages, Family-Style
  ≈ Catering …) stay separate pages, but each has its own intent and angle
  (`CONTENT_ARCHITECTURE.md` §4). No copied paragraphs; link instead.
- **Placeholder pages are noindex** (`robots: { index: false }`) until
  approved content exists. `/design-preview` is dev-only (404 in production).
- **No individual pages per menu item** (thin, near-duplicate content).
  Items live in category tables. An item can get a blog guide only if it
  has enough unique, helpful content.
- **No separate "calories" pages per category.** Calories are a column in
  the same category table.
- A blog article must not target the same intent as a category page.
  Example: `/desserts` covers dessert prices; a blog post can cover a
  genuinely different question.
- No unnecessary keyword variations (no separate "prices", "menu",
  "near me" versions of the same page).
- Before adding any page, check the content plan for an existing page with
  the same intent.

## 2. Metadata (per page)

Use the Next.js Metadata API (`export const metadata` or `generateMetadata`).

| Field | Rule |
|---|---|
| `title` | Unique, ~50-60 chars. Root layout sets a template: `%s | {Site Name}` |
| `description` | Unique, ~140-160 chars, natural language |
| `alternates.canonical` | Self-referencing canonical on every page |
| `openGraph` | title, description, url, type (`website` or `article`), image |
| `twitter` | `summary_large_image` |
| `robots` | Default index/follow; `noindex` only for 404 and utility pages |

- Root layout sets `metadataBase` from `lib/site.ts`, which reads the
  `NEXT_PUBLIC_SITE_URL` env var (fallback `http://localhost:3000`).
  The production domain is never hardcoded; it is set in Vercel before launch.
- Year in titles (e.g. "2026") only if the page is actually kept updated.

## 3. Structured data (JSON-LD)

Render as `<script type="application/ld+json">` inside the page, using
`JSON.stringify(data).replace(/</g, "\\u003c")` (per Next.js docs).
Use one reusable `JsonLd` component.

| Page | Schema types |
|---|---|
| Homepage | `WebSite`, `Organization` (the blog itself, not Olive Garden) |
| `/menu` hub | `BreadcrumbList` |
| Category pages | `BreadcrumbList` (`Home > Menu > Category`); `FAQPage` only if a visible FAQ exists |
| Blog articles | `BlogPosting` (headline, dates, author, image), `BreadcrumbList`, `FAQPage` if visible FAQ |
| About / Contact / legal | `BreadcrumbList` |

**Do not use:** `Restaurant`, `Menu`/`MenuItem`, `Product`, `Offer`,
`AggregateRating`, or `Review`. These would misrepresent the site as the
restaurant or a seller. FAQ schema must match visible on-page FAQ text exactly.
(Note: Google shows FAQ rich results only for limited sites, but the markup is
still valid and harmless when it matches the page.)

## 4. Sitemap and robots

- `app/sitemap.ts` builds the list from the same data files used by the pages
  (published categories + blog posts), so new content is added automatically.
  Noindex pages (placeholders, `/menu` until approved) are left out.
- `lastModified` uses each item's real `updatedAt` date, never `new Date()`.
- `app/robots.ts` allows all crawlers and points to `/sitemap.xml`.
- Vercel preview deployments should not be indexed (Vercel adds
  `X-Robots-Tag: noindex` on preview URLs by default; verify after deploy).

## 5. Internal linking plan

- Header: Home, Menu (`/menu`), Blog, About. Full plan: `INTERNAL_LINKING.md`.
- Footer: all categories, key guides, legal pages.
- Homepage links to featured categories, `/menu`, and the latest guides.
- `/menu` links to every category page.
- Each category page links to 2-5 related categories and 1-2 related guides.
- Each blog article links to the relevant category pages in the body and
  shows 3 related articles at the bottom.
- Breadcrumbs on every page except the homepage.
- Use descriptive anchor text ("Olive Garden dessert prices"),
  not "click here". Vary anchor text naturally; no keyword stuffing.

## 6. On-page content guidelines

- One `<h1>` per page that matches the page intent.
- Logical heading order (`h2` → `h3`), used to build the table of contents.
- Short intro answering the main question first (e.g. price range).
- Price tables near the top of category pages.
- "Prices last checked: {date}" + "Prices vary by location" note.
- Write for people first: helpful, specific, honest. No filler or stuffing.
- Show the author/editor name and the "last updated" date on articles (E-E-A-T).
- Mark unverified data visibly ("Not verified yet") instead of guessing.

## 7. Performance (helps SEO)

- All pages statically generated at build time (`generateStaticParams`
  for `/[category]` and `/blog/[slug]`; must return at least one param
  because `cacheComponents` is enabled).
- `next/image` for all images, with correct `width`/`height`/`sizes`,
  `priority` only for the main above-the-fold image.
- `next/font` for fonts (self-hosted, no layout shift). Max 2 font families.
- Server Components by default; `"use client"` only where needed
  (e.g. mobile menu toggle).
- No heavy third-party scripts. Analytics (if any) added later with care.
- Targets: Lighthouse 90+ on mobile; LCP < 2.5s, CLS < 0.1, INP < 200ms.

## 8. Launch SEO checklist

- [ ] `NEXT_PUBLIC_SITE_URL` set to the new production domain in Vercel
  (new domain; no existing website is migrated or redirected)
- [ ] Every page has unique title + description + canonical
- [ ] `/sitemap.xml` and `/robots.txt` load correctly
- [ ] Structured data passes Rich Results Test / Schema Validator
- [ ] Open Graph image renders when sharing a link
- [ ] 404 page works and returns status 404
- [ ] Google Search Console verified and sitemap submitted
- [ ] No placeholder prices shown as real values
